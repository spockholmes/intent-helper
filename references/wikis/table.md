# 表结构维护（Table）

## Why

沉淀表结构知识，让意图文档直接引用，不必重复说明字段定义。作为建表和团队沟通的依据。


## 核心规则

- **已有表**：直接引用表文档，只引用关键字段名（剪裁）
- **新表**：引导用户提供必须信息（表名、表说明、表结构），生成表文档并纳入知识库
- **表结构变更**：同步更新表文档
- **采用总-分结构**：总览负责索引，表文档记录表名、表说明、表结构

## 引用路径规范

## 已有表：读取并引用

### 流程
1. 用户提及表名（如"orders 表"）
2. 检查 `.project-info/wikis/table-wiki/表定义/` 下是否存在对应文档
3. **存在**：读取表文档，了解字段定义
4. 在意图文档中生成相对路径链接，只引用关键字段名（剪裁）

### 引用格式示例
```markdown
> **数据来源**：[orders](../../../wikis/table-wiki/表定义/orders.md) 表的 `paid_amount` 字段
```


## 新表：对话设计 + 生成表文档

### 流程
1. 用户提及的表在知识库中不存在
2. 主动询问："该表尚未录入知识库，需要现在设计吗？"
3. 用户确认 → 在对话中引导填写必须信息：
   - **表名**：如 `point_flow`
   - **表说明**：这个表是做什么的，数据来源（本系统生成 / 由 XXX 系统同步）
   - **表结构**：每个字段的字段含义、字段名、字段类型、是否可空、是否唯一、默认值、外键、是否索引、备注
4. 设计完成后 → 生成表文档，保存至 `.project-info/wikis/table-wiki/表定义/表名.md`
5. 更新 `.project-info/wikis/table-wiki/总览.md` 索引
6. 意图文档中生成相对路径链接

### 按需补充（如有）
只写 AI 不知道、且影响理解或执行的信息：
- 复杂的关联关系
- 特殊的索引设计
- 影响决策的数据量级
- 项目特有的约束（如"不可物理删除"）

### 剪裁
不写 AI 能从代码或数据库读到的信息（建表语句、变更历史等）。


## 文档模板

### 表文档（`表定义/表名.md`）

```
# 表名：`表名`

## 表说明
> 简述这个表是做什么的。
>
> 数据来源：本系统生成 / 由 XXX 系统同步

## 字段定义
| 字段含义 | 字段名 | 字段类型 | 是否可空 | 是否唯一 | 默认值 | 外键 | 是否索引 | 备注 |
|---------|--------|---------|---------|---------|--------|------|---------|------|
| 主键ID | id | bigint | 否 | 是 | 自增 | 无 | 是 | 主键 |
| ... | ... | ... | ... | ... | ... | ... | ... | ... |

## 补充说明（按需）
> 只写 AI 不知道、且影响理解或执行的信息。
```

### 字段定义模板说明

| 列 | 含义 |
|----|------|
| 字段含义 | 字段的业务含义，便于人阅读 |
| 字段名 | 数据库实际字段名 |
| 字段类型 | 如 bigint、varchar(20)、decimal(10,2) |
| 是否可空 | 是 / 否 |
| 是否唯一 | 是 / 否 |
| 默认值 | 无 / 具体值 / 自增 |
| 外键 | 无 / 关联表.字段 |
| 是否索引 | 是 / 否 |
| 备注 | 取值范围、关联关系、注意事项等 |
