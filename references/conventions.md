# 公共约定维护（Conventions）

## Why

沉淀项目特有的、反复用到的约定，避免每次沟通重复说明，让 AI 在多个任务中保持一致。


## 核心原则

**剪裁原则**：如无必要，勿增实体——不必要的内容不加，必要的内容尽量精简。

- **不写**：AI 已知的通用语法、框架默认行为、业界通用规范
- **只写**：项目特有的技术选型、团队约定的特殊规则、非默认的架构决策


## 目录规范

```
.project-info/wikis/conventions/
├── 总览.md          # 总入口（必须存在）
└── 约定/            # 子文档目录（复杂后出现）
    ├── 编码规范.md
    ├── API规范.md
    └── Git规范.md
```

### 拆分条件
当约定涉及 ≥3 个独立领域时，自动拆分 `总览.md` 到 `约定/` 子目录。


## 维护流程

### 自动识别
AI 在以下场景中主动识别并建议纳入公共约定：

| 场景 | 示例 |
|------|------|
| 用户重复描述同一规则 | 多次提到"金额用 BigDecimal" |
| 用户明确表达偏好 | "以后都按这个来" |
| 用户提出项目特有规则 | 明显不属于 AI 已知的通用知识 |

### 建议方式
AI 在对话中主动提出建议，但不直接写入，等待用户确认后才执行。

**示例**：
> "注意到你在多个场景中都提到'所有金额用 BigDecimal 处理'，这是项目特有的规则，建议纳入公共约定。是否要添加？"

### 写入
用户确认后，按总-分层次维护——总览负责索引，子文档记录具体约定。只记录必要的，不堆积冗余。

### 动态维护
- 发现内容过时 → 提醒调整
- 发现内容多余 → 提醒清理
- 发现不符合四原则 → 提醒调整
- 发现需要纳入 → 提醒添加


## 文档模板

### 总览文档（`总览.md`）

```
# 项目公共约定

> 本文件仅记录项目特有的约定，不包含AI已知的通用知识。

## 1. 约定索引
> - [编码规范](./约定/编码规范.md)
> - [API规范](./约定/API规范.md)
> - [Git规范](./约定/Git规范.md)

## 2. 全局约束
> - 技术栈：Java 17 + Spring Boot 3.2
> - 所有金额字段使用 BigDecimal
> - 响应格式：`{code, message, data}`
```

### 子文档模板（`约定/XXX.md`）

```
# [领域]规范

> 仅记录项目特有约定，不重复通用知识。

## 规则列表
> 1. [具体规则]
> 2. [具体规则]

## 示例（如有）
> ...
```


## 交互示例

**场景一：AI 自动识别并建议**

**用户**："积分金额要用 BigDecimal，不能用 double。"

**AI**：
> "注意到这是项目特有的类型约束规则（'金额用 BigDecimal'），建议纳入公共约定。是否要添加？"

**用户**："可以。"

**AI**：已添加到 `约定/编码规范.md`。

**场景二：冗余规则，AI 建议剪裁**

**用户**："加一条：Java 用大驼峰命名。"

**AI**：
> "大驼峰（PascalCase）是 Java 语言的通用命名规范，AI 已知此类常识，不建议写入公共约定。公共约定应只记录项目特有的规则，避免冗余信息。"
